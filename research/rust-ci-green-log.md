# Research log: rust-ci-green

Recipe: ../recipes/rust-ci-green.md
Checked: 2026-10-19
Tiers: T1 = official or primary, T2 = secondary, T0 = from memory.

## Requirements

1. A follow-up to rust-ci-github-actions: the pipeline exists and was
   merged while tests and some components still fail.
2. Transferable to any repository the CI recipe was used on, written in
   the same style as that recipe.
3. Audit, identify, and bring every failing crate or component to a pass
   on genuine tests, one by one, and get each fix merged.
4. No follow-up prompt needed. No wording that invites questions,
   stopping, or a report; the agent acts within a narrow window without
   being overly specific.
5. Minimal language, optimized like the revised CI recipe: smallest
   change that keeps what the product does, no new documents, least
   disruptive option.
6. Hard rule 10 must transfer to any repository and agent: use
   auto-merge where available, merge directly where it is not, and give
   the agent no reason to stop and ask how to merge.
7. Fixes land one at a time, so a fix's pull request can still show
   failures that later fixes cover; the merge rule must let it land.
